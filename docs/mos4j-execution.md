# MoS4J 推进方案

> 配套：[整体方案 `mos4j-port-plan.md`](mos4j-port-plan.md)（为什么这么设计）、[任务列表 `mos4j-tasks.md`](mos4j-tasks.md)（做什么）。
> 本文件回答：**怎么一步步推**——阶段顺序、每阶段的动作剧本、CI 门、检查点、评审规范、协作流程、停点汇报格式。
> 路线：**A（全量 Java 移植）**；驱动力 = 团队技术栈；Go 仓库只读。

---

## 1. 推进原则

| # | 原则 | 落地方式 |
|---|---|---|
| 1 | **垂直切片，不是分层交付** | 每个里程碑交付一个**能跑的场景**，不是「做完了某层」。J1 的验收是「读文件 → 作答跑通」，不是「llm 模块写完了」 |
| 2 | **停点制** | 每个里程碑结束**停下汇报**，等确认再进下一个。不自动往下滚 |
| 3 | **先契约后实现** | J0 未过不写实现代码。实现期发现契约缺项 → 回到契约补，**不在代码里就地发明** |
| 4 | **每条任务自带测试** | 没有测试的任务不算完成。MoS 的不变式是**合入门**，不是愿望清单 |
| 5 | **漂移靠机器拦，不靠人记** | 字段名静态守护 + 场景测试进 CI（§4 三道防线） |
| 6 | **语义对齐 MoS** | 拿不准 → 看 MoS 怎么做、**为什么这么做**（§6 决策树）。不自创机制 |
| 7 | **诚实降级** | Java 侧不等价的地方**写进文档 + `Describe()` 快照**，不假装等价（MoS 纪律：假装有边界比没有边界更危险） |
| 8 | **不扩大范围** | M3+（多智能体 / MCP / Skills / 插件化）不在本次范围。发现需要 → 写建议，不顺手做 |

## 2. 阶段推进模型

```
   ┌── J0 契约冻结 ──┐   ┌── J1 最小切片 ──┐   ┌── J2 安全纵深 ──┐
   │ 语料 + 契约     │ → │ 端到端跑通     │ → │ 双轨制 + 审批  │
   └─────────────────┘   └─────────────────┘   └─────────────────┘
        ▲ 门 G0               ▲ 门 G1              ▲ 门 G2
        │                     │                     │
   ┌────┴──────┐        ┌─────┴──────┐        ┌─────┴──────┐
   │ J3 文件沙箱│        │ J4 上下文  │        │ J5 工具联网│
   └───────────┘        └────────────┘        └────────────┘
        ▲ 门 G3               ▲ 门 G4              ▲ 门 G5
        │                     │                     │
   ┌────┴──────────┐
   │ J6 三协议+硬化│
   └───────────────┘
        ▲ 门 G6
        │
   ┌────┴──────────┐
   │ J7 技能+J3 升级│  （B16 Jackson 3 + Go skill 机制）
   └───────────────┘
        │
   ┌────┴────────────────┐
   │ J8 三平台路径强制    │  （Seatbelt 对齐 + Linux Landlock；Windows 未做）
   └─────────────────────┘
        │
   发布准备（后续立项：坐标/签名/Central/文档站）
```

**每个里程碑内部的三段式**（Go 版 MoS 的做法）：

| 段 | 内容 | 占比 | 产出 |
|---|---|---|---|
| **契约对齐** | 读 Go 侧对应实现 + 整体方案对应小节 → 写出「这个机制在 Java 侧怎么做 + 为什么」 | ~20% | 一段「实现说明」（进 PR 描述） |
| **实现** | 写代码 + 写测试 | ~60% | 代码 + 测试 |
| **对拍 + 硬化** | 场景测试 + 不变式测试 + 边界/依赖检查 | ~20% | 绿灯 |

**时间盒规则**：单个任务超出估算 **1.5 倍** → 停下，把任务拆小或改方案，**不硬扛**。超支往往意味着契约没读透或方案有洞——这两件事都比超时更贵。

### 3.1 J0 契约冻结（~1.6 周）

> 定位（整体方案 §0.0）：参考实现，无跨语言对拍；L1 报文从 Go 测试字面量抄，L2/L3 Java 自建。

| 批次 | 天 | 动作 | 产出 | 自检 |
|---|---|---|---|---|
| B1 | 1–2 | 通读 Go 的 `docs/ARCHITECTURE.md` §1–§3.13 + `session/` + `agent/execpath/` + `agent/hook/` + `tool/tool.go` + `filesystem/sandboxed.go` | 读书笔记 | 每条机制能用自己的话说出「不这么做会出什么事」 |
| B2 | 2–3 | 写 `INVARIANTS.md`（七条）+ `MECHANISMS.md`（十条） | D1 / D2 | 每条有后果说明 + 验证方式 |

| B4 | 4–5 | L1 报文从 Go 测试字面量抄入 `src/test/resources/llm/` + 场景测试骨架（`@Disabled`） | T0.5 | 每份报文与 Go 测试字面量一致 |

### 3.2 J1 最小垂直切片（~3.7 周）

| 批次 | 天 | 动作 | 关键守则 |
|---|---|---|---|
| B1 | 1–2 | `mos4j-llm` 值类型 + 序列化对齐 | `ToolCall.args` 保持 **String 原始 JSON**；**手写 Serializer** 对齐 Go 的 `omitempty` 语义 |
| B2 | 3–4 | OpenAI 协议 DTO + 非流式 | |
| B3 | 5–6 | OpenAI 流式 | `[DONE]` 判定；`arguments` **按 index 累加**；截断 → `ErrStreamTruncated`；**结束原因为空 ≠ 截断** |
| B4 | 6–7 | usage 归一 + 传输层 | `freshInputTokens` 去缓存口径；分项和 = 总计 |

| B7 | 11–12 | 投影自愈（`projectSeq`） | 合成回执**按声明序补在首个非 tool/result 事件之前** |
| B8 | 12–13 | `mos4j-driver` + ReAct | 事件序列固定；先落全部 `tool/call` 再执行；截断工具调用拒绝 |
| B9 | 13–15 | `mos4j-execpath` | 回填序 = 调用序；错误即结果；逐条独立裁决 |
| B10 | 15–16 | `mos4j-driver/agent`（Config / Agent / Describe；**不落 core**，见整体方案 §3.1 特例 4） | `Describe()` 写明**装了什么 + 没装什么** |
| B11 | 16–17 | L1/L2 场景点亮 + 端到端 | **G1 门** |

**J1 的验证顺序（重要）**：先让**假 LLM 服务**（`com.sun.net.httpserver`）回放 L1 场景，让 L2 场景全绿，**再**接真实模型。顺序反了会把「场景失败」和「模型行为问题」混在一起，排查成本翻倍。

**J1 的最大风险**：以为「跑通一个 turn」= 移植完成。J1 只证明**骨架正确**，不证明语义对齐。语义对齐是 J2 的 L3 场景才开始验证的。

**J1 当前状态（2026-11-05）**：B1–B10 已落代码并有测试，B11 部分完成；**G1 门待人工评审**。
逐项完成情况、真实构建输出、跳过项与未完成项见 [`contract/J1-STATUS.md`](contract/J1-STATUS.md)（唯一权威口径，不在本文件重复维护）。

### 3.3 J2 安全纵深（~2.5 周）

| 批次 | 天 | 动作 | 关键守则 |
|---|---|---|---|
| B1 | 1–2 | HookBus | waterfall；执行前快照链；`ErrNilHookEvent`；未表态 = allow |
| B2 | 2–3 | GuardBus | **两个总线的 API 互不出现对方类型**（结构性保证） |
| B3 | 3–4 | 载荷冻结接线（preflight + execute 两处） | 改写 name/args/id 任一 → 拒绝 |
| B4 | 4–5 | 策略层（名字级 + 参数级） | `Allow` 空集 = 全禁（与未配置语义不同）；`Deny` 优先；参数解析失败 = 拒绝 |
| B5 | 5–7 | 审批（四档 + Answerer + Service + 审计事件） | 未装配 → 拒绝；批准只对本次生效；通道报错 ≠ 人拒绝 |
| B6 | 7–8 | 文案固定 + L3 场景 | **拒绝文案照抄 Go**（含「不许绕」半句）；语义等价的小差异须 PR 说明 |
| B7 | 8–9 | 零开销降级测试 + Go 不变式测试译制 | `TestGuardVerdictNotBypassableByHooks` 必须有 Java 对应项 |
| B8 | 9–10 | G2 门 | |

**J2 的最大风险**：**把 Guard 与 Hook 合成一条链**（Java 的 lambda 组合很顺手）。一旦合成，「钩子绕过守卫」就只是约定而非结构。**对策**：T-INF.3 的边界检查里加一条断言——`hook` 包的类型签名里不出现对方类型。

**J2 当前状态（2026-11-05）**：B1–B7 已落代码并有测试；T2.1–T2.10 完成，T2.11 部分完成（Go 侧原测试名待授权后抄录）；**G2 门待人工评审**。
逐项完成情况、真实构建输出、场景计数与未完成项见 [`contract/J2-STATUS.md`](contract/J2-STATUS.md)（J2 的唯一权威口径）。

### 3.4 J3 文件与沙箱（~2.9 周）

| 批次 | 天 | 动作 | 关键守则 |
|---|---|---|---|
| B1 | 1–3 | jail 双校验 + 新建路径向上回溯 | **读也走 Realpath**；`root/escape/new.txt` 必须被拒 |

**J3 的最大风险**：**在 macOS 上把 `/tmp` 与 `os.TempDir()` 当默认可写根**。Go 版明确刻意不含（共享临时目录是符号链接攻击的经典目标）。Java 侧 `System.getProperty("java.io.tmpdir")` 同理——**不自动加入可写根**。

**J6 的最大风险**：**取消漏检**（Java 没有 ctx 强制力）。对策：T6.4 的「可阻塞点清单」逐项勾选 + 每项一个取消测试；清单随代码走（放在 `mos4j-core` 的文档里，PR 模板勾选）。

### 3.8 J7 技能机制 + Jackson 3 升级（~1.2 周，2026-11-07 已收口）

| 批次 | 动作 | 关键守则 |
|---|---|---|
| T7.1 | **B16：Jackson 3 升级**（J7 的前置） | databind/core 包名迁 `tools.jackson.*`，注解仍 `com.fasterxml.jackson.*`；**不要手写 YAML 子集**；`FAIL_ON_TRAILING_TOKENS` 新口径要与 Go `json.Unmarshal` 对齐并钉测试 |
| T7.2–T7.3 | 目录发现 + frontmatter + 清单渲染 | 坏技能跳过但**留诊断**；清单多级降级且丢了多少**如实写**；渲染是纯函数（prompt cache） |
| T7.4–T7.5 | `skill` 工具 + 重扫 | 正文**调用时现读**；**审计先于返回正文**；重扫显式幂等全量、原子快照替换 |
| T7.6–T7.8 | `/name` 手势 + 事件 + 提示词 | 手势只在首 token；`skill` 事件不进投影；`skills` 段插在 `context` 与 `instructions` 之间 |
| T7.9–T7.11 | SDK / Starter 接线 + 测试 | Starter 相对目录锚 `mos4j.workspace`；工具面 13 → 14 但 **条件注册** |

**J7 的最大风险**：**造出第二套安全真相**（把 `allowed-tools` 做成真工具收窄）。对策：`allowed-tools` 只求交、只留痕；技能正文走专用工具而不是 `read`；审计落点不碰 `ExecPath.Security`。
已收口证据见 [`contract/J7-STATUS.md`](contract/J7-STATUS.md)。

### 3.9 J8 三平台路径强制（2026-11-07 已收口 macOS + Linux 代码面）

| 批次 | 动作 | 关键守则 |
|---|---|---|
| T8.1 | Seatbelt 与 Go 对齐 | `(literal "/dev/null")` 必须放行；写根要 `toRealPath`（软链根会拦自己的写）；执行器缺失在 `wrap` 阶段就报错 |
| T8.2 | `PathScopes` 语义修正 | `supported()` = 「有可用后端」；`derive(workDir)` = Go 的 `deriveScope`；无后端平台报错而不是静默 |
| T8.3 | Linux Landlock（FFM） | 零依赖零 JNI：`landlock_create_ruleset`/`add_rule`/`restrict_self` + `prctl`；ABI V1/V2/V3 分档；`restrict_self` 只对调用线程生效 → **必须重新执行自己** |
| T8.4–T8.5 | fail-closed 管道 + SDK 缺省装配 | `wrap` 抛错 → `notStarted`（命令不跑）；SDK 写根 = 工作区（与 Go 缺省强制同口径） |
| T8.6–T8.8 | 测试 + 真机验收 + Windows | 非 Linux 上 5 条 Landlock 用例是**跳过不是通过**；Windows 未做（需验证环境，8–12 人日） |

**J8 的最大风险**：把「后端已实现」当成「已验收」。对策：三平台能力矩阵写进 [`contract/J8-STATUS.md`](contract/J8-STATUS.md) §2，每条右列必须写实测状态；缺省装配会让「宿主不允许应用沙箱」的机器上 shell 命令直接失败——这是 fail-closed 的意图，但升级前必须知道。
已收口证据见 [`contract/J8-STATUS.md`](contract/J8-STATUS.md)。

## 4. 防漂移体系（三道防线）

> 定位（整体方案 §0.0）：参考实现，无跨语言机器对拍。三道防线拦截的是 **Java 版自身的漂移**（实现中途语义走样、字段名手抖、公共 API 静默变形），不是 Go↔Java 对拍。

### 防线 1：字段名静态守护（结构性）

| 项 | 内容 |
|---|---|
| 原理 | 从 Go 源码抽 `json:"..."` tag 一次性生成冻结清单（`fieldnames.json`）→ Java 序列化键集合必须与清单**完全一致** |
| 实施 | `tools/fieldname-extract/`（一次性抽取）+ `FieldNameContractTest`（Java 断言） |
| 拦截什么 | 事件字段改名 / 增删 / 拼写差异（camelCase vs snake_case 混用被打破） |
| 什么时候红 | Java 侧有人改了事件字段 → 测试红 → 改清单 + 改 DTO 同一 PR 评审 |
| 成本 | ~1 人日（J0 的 T0.4 + T0.8） |

### 防线 2：场景测试（语义性）

> 场景设计照抄 MoS 的踩坑记录（这是「参考 MoS」的价值本体），期望值 Java 自算。

| 层 | 验什么 | 断言口径 |
|---|---|---|
| L1 | `content` / `toolCalls` / `finishReason` / `usage` 四元组 | 与 Go 测试的断言语义一致（usage 分项和 = 总计的不变式同时验） |
| L2 | `messages()` 投影行为 | 压缩遮蔽 / 合成中断回执 / 孤儿 turn 修复的行为正确性 |
| L3 | `Outcome`（content / isError / 顺序）+ 拒绝理由 | 理由与文案表（§4.3）一致；顺序严格等于调用序 |

**回补路径**（将来需要与 Go 版互操作时，见整体方案 §0.0②）：捡回导出器 + Go 基线，把防线 2 升级为真对拍——契约文档与字段名冻结使这一步是增补不是重构（估算 ~4 人日，见任务列表按需清单）。

### 防线 3：PR 模板 + 评审（人为性）

PR 描述必须勾选：

- [ ] 本次改动触及哪条不变式（列出编号）
- [ ] 本次改动触及哪个机制（列出编号）
- [ ] 对应的场景测试（列出用例名）——**没碰场景要说明为什么**
- [ ] 是否引入自创机制（是 → 必须附理由 + 风险 + 对位分析）
- [ ] 是否改动公共 API / 事件字段（是 → 必须写迁移说明）
- [ ] 依赖审计与边界检查是否绿

**评审规则**：
- 触及**事件契约 / 载荷冻结 / Guard-Hook 结构**的 PR → **必须两人评审**（含维护者）。
- 触及**协议层**的 PR → 至少一人对着 Go 侧实现核对语义。
- 纯新增工具（不改共享语义）→ 一人评审 + 场景补测。

## 6. 决策树：机制拿不准怎么办

```
拿到一个机制，Java 侧不知道怎么实现
   │
   ├─ 1. 查整体方案 §2（十个机制）── 命中 → 按方案做
   │
   ├─ 2. 查 Go 侧实现 + 注释 ──────── 命中 → 照契约做（注释里通常写了「为什么」）
   │
   ├─ 3. 查 Go 的 ARCHITECTURE.md ─── 命中 → 按契约做
   │
   ├─ 4. 查六处差异表（§5）──────── 命中 → 按降级方案做 + 写降级声明
   │
   └─ 5. 都没有 → 走「自创机制登记」流程（下）
```

**自创机制登记流程**（Go 版 AGENTS.md 的纪律，Java 版对位）：

1. 写清楚：**MoS（Go）怎么做** + **为什么 Java 不能照做**；
2. 写清楚：**Java 侧怎么做** + **代价**；
3. 写清楚：**这是自创**（MoS 与 PI/DSH 都没有等价物）→ 登记到 `docs/contract/SELF-INVENTED.md`；
4. **自创的机制不许放宽任何 fail-closed 分支**；
5. 提交评审时**单独列出**，让评审者重点看。

**明确不做的事**：不因为「Java 写起来更方便」就改变语义。Java 的表达优势体现在**实现形态**（虚拟线程、Jackson、record），不体现在**语义**。

## 7. 与 Go 侧的协作流程

### 7.1 边界

| 项 | 规则 |
|---|---|
| Go 仓库 | **只读**。不修改任何文件（含 `docs/`、`.DS_Store`） |
| 发现 Go 侧缺陷 | 写成建议交给你：`docs/proposals/go-<topic>.md`（现象 / 影响 / 建议 / 是否影响 Java 侧同名机制） |
| 需要 Go 侧配合 | 走 PR 建议，不直接改 |
| Java 版协议层 | 是**新产物**，与 moproto 做**口径对齐**，不反向改 Go 侧 |

### 7.2 与 Go 侧变更的关系

Go 侧演进**不自动触发** Java 侧跟进（参考实现，无对拍 CI）。但：

- 每月契约漂移检查（§10.1）时**看一眼** Go 的 ARCHITECTURE/PRD 变更记录；
- 若 Go 侧修了一个 MoS 也有的机制 bug（如流完整性判定的新网关形态）→ 评估是否回填 Java 侧，回填走正常 PR + 场景补测；
- 若需要与 Go 版互操作（消费 Go 会话日志）→ 触发按需清单的对拍回补（整体方案 §0.0②）。

### 7.3 与 Go 版的关系口径

| 项 | 口径 |
|---|---|
| Java 版定位 | **参考 MoS 的独立 Java 实现**——不是从属副本，也不承诺逐字节一致 |
| 语义权威 | **机制语义以 MoS 为准**（不变式/机制/文案照抄）；实现形态 Java 自主 |
| Go 侧缺陷 | 写建议交给你；不反哺、不代改 |
| 漂移控制 | 防线 1–3（§4）拦 Java 自身走样；与 Go 的分叉靠「语义对齐 MoS」的评审纪律 + 回补路径兑底 |

## 10. 节奏、并行与回滚

### 10.1 节奏

| 周期 | 内容 |
|---|---|
| 每日 | 提交前跑 `mvn -q verify`；勾选任务清单；更新 PR |
| 每周 | 任务清单复盘：完成项打勾、超支项标时间盒、下周计划 |
| 每里程碑 | **停点汇报**（§8 模板）+ G 门评审 |
| 每月 | 契约漂移检查：看一眼 Go 侧 ARCHITECTURE/PRD 变更 → 是否有值得回填的机制修复（§7.2） |

### 10.2 并行（2 人时）

| 阶段 | 可并行 | **不可并行（单点）** |
|---|---|---|
| J0 | 契约文档 / 场景骨架 | 字段名冻结清单（一人产出） |
| J1 | 协议层 / session+tool | **事件契约**（一人改）；`mos4j-execpath` |
| J2 | hook+policy / approval | **Guard-Hook 编排点** |
| J3 | fs / sandbox | — |
| J4 | 压缩 / 提示词+上下文文件 | — |
| J5 | builtin / web | — |
| J6 | 协议适配 / 硬化 | — |

**铁律**：`mos4j-session` 的事件 DTO + `mos4j-llm` 的值类型 + `mos4j-execpath` 的编排点，**任何时候只能一人改**。这三处是语义的地基，分叉 = 漂移。

### 10.3 回滚

- 每个里程碑是一串**独立 PR**，可整体回退到上一个 G 门的状态；
- 语义变更（字段名、拒绝文案、事件序列）**单独一个 PR**，便于定位与回滚；
- 场景期望值**只在语义有意变更时更新**，且 diff 必须能看出「哪条语义变了」；
- 出现大面积语义偏差时，**回到上一个 G 门**重新验证，而不是在偏差上打补丁。

## 11. 明确不做的事（推进过程中反复确认）

| 不做 | 在推进中的具体表现 |
|---|---|
| 不逐行翻译 | 遇到「Go 里这么写」时先问「**为什么**这么写」；能说清原因才照做，说不清就查 ARCHITECTURE |
| 不复刻 moproto 全量 | 协议层只写 MoS 实际消费的调用面 |
| 不在 SDK 引入 Spring/DB/ORM | Spring 只在 starter 模块（T-INF.2 会拦） |
| 不用 JDK 默认正则 | T-INF.2 的源码扫描会拦 |
| 不放宽 fail-closed | 任何「这里降级一下更友好」的念头 → 停下写建议 |
| 不改 Go 仓库 | 全程只读（无导出器，仅参考阅读与静态抽取）；发现缺陷写建议 |
| 不做 M3+ | 发现多智能体/MCP/Skills 的需求 → 写进「后续立项建议」，不实现 |
| 不在没有具体 Spring 宿主需求时做 starter | 「能力即证据」：starter 在按需清单（任务列表 §10） |
| 不假装有边界 | 进程组、版本令牌、Schema 反射的降级全部写进文档与快照 |
| 不扩大范围 | 任何「顺手加个功能」的想法 → 记入后续建议 |
| 不在没拍板时往下滚 | 里程碑结束停下汇报，等确认 |
